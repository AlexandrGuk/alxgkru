# Mood News Grid

Тестовое задание: одна лента реальных новостей, четыре эмоциональных режима. Факты не меняются. Живая страница: [alxgk.ru/mood-news-grid/](https://alxgk.ru/mood-news-grid/).

## Как запустить

Нужен любой статический сервер из корня `alxgkru` (иначе `data/news.json` не загрузится с `file://`).

```bash
php -S localhost:8000
```

Открыть http://localhost:8000/mood-news-grid/

Обновить снимок новостей:

```bash
cd mood-news-grid
node scripts/fetch-news.mjs
```

После этого тона нужно переписать заново (см. ниже) и собрать датасет:

```bash
node scripts/build-news.mjs
node scripts/verify-facts.mjs
```

Проверка без переписи: достаточно открыть страницу — в репозитории уже лежит снапшот `data/news.json`.

## Откуда новости

Источник: полнотекстовый RSS РБК  
`https://rssexport.rbc.ru/rbcnews/news/30/full.rss`

Скрипт `scripts/fetch-news.mjs` забирает фид, выкидывает короткие материалы и сохраняет 12 сюжетов в `data/raw.json`. Дата снятия этого снапшота — **18 августа 2026**. Выдуманных новостей нет. У каждой карточки есть канонический URL РБК.

Lenta.ru RSS как первый кандидат отпал: в ленте пустые `<description>`, полного текста нет.

## Как хранятся данные

Структурированный JSON, не база.

| Файл | Роль |
|---|---|
| `data/raw.json` | сырой снимок RSS |
| `data/news.json` | канон + факты + четыре переписи + результат проверки |
| `scripts/rewrites.mjs` | тексты тонов, из которых собирается `news.json` |

Поля карточки: `title`, `originalText`, `url`, `publishedAt`, `sourceName`, `facts`, `rewrites.{neutral,joyful,sad,ironic}`.

Демо читает только `news.json`. Ключ нейросети ревьюеру не нужен.

## Как переписывается тон

Нельзя заранее набить настроения руками как отдельные «фейковые новости». Пайплайн такой:

1. Забрать оригинал из RSS.
2. Собрать канон фактов: имена, места, даты, числа, дословные цитаты.
3. Переписать заголовок и текст в четырёх режимах **только из этого канона**.
4. Прогнать `verify-facts.mjs`. Если проверка не прошла — текст чинится, а не публикуется «на глаз».

Режимы:

- **нейтрально** — сухая сводка;
- **радостно** — более живая лексика, без новых событий;
- **грустно** — акцент на потере, паузе, неравенстве, которые уже есть в тексте;
- **иронично** — сухой комментарий к тем же фактам.

Трагические сюжеты не «празднуются»: радостный тон там — энергия формулировок, не радость от жертв.

Перепись в этом снапшоте сделана моделью **Cursor Grok 4.6** в сессии разработки. Отдельный API-ключ в репозиторий не клался.

Промпт, которым можно повторить шаг 3 с любой LLM:

```
Перепиши новость в тоне: нейтрально / радостно / грустно / иронично.
Нельзя добавлять факты, числа, имена, места, даты и цитаты, которых нет в оригинале.
Нельзя выкидывать элементы из списка keep и quotes: они должны встретиться в тексте дословно.
Тон меняет лексику и ритм, не сюжет.
Сохрани прямую речь в кавычках без перефраза.
```

## Как проверяется сохранение фактов

`scripts/verify-facts.mjs` для каждой пары «новость × тон»:

1. Все строки `facts.keep` есть в переписи как подстроки (имена, ключевые числа, места).
2. Все `facts.quotes` есть дословно.
3. В переписи нет **новых** значимых чисел: годы, проценты, `тыс./млн/млрд`, суммы с `€`/`$`. Если числа не было в оригинале — fail.

Мелкие целые вроде «2 концерта» специально не считаются доказательством нового факта: слишком много ложных срабатываний на русском. Их страхует список `keep`.

На карточке сравнения: чипы имён/мест/дат, бейдж «Факты совпали», ссылка на оригинал РБК.

Сейчас снапшот: `OK 12 items × 4 moods`.

## Что использовали из AI

- Cursor Grok 4.6: план, перепись тонов, вёрстка, канон фактов.
- Автопроверка фактов — обычный скрипт, не модель.
- RSS РБК — открытый фид, не генерация новостей.

## Ограничения

- Это снимок, не прямой эфир. Без ключа страница всё равно работает.
- После `fetch-news.mjs` набор URL сменится — тона из `rewrites.mjs` придётся писать заново.
- Перепись короче оригинала на длинных статьях. Опускать второстепенный фон можно, добавлять нельзя.
- Грамматические формы имён в `keep` иногда зафиксированы как в исходнике («Матвею Сафонову») — проверка нарочно строгая.
